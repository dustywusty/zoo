zoo. agents in cages, one way out

zoo runs any AI coding agent (Claude Code, Codex, anything) inside a small sandbox per worktree. The sandbox's only route anywhere is a logging, allowlisting gatekeeper. A local dashboard shows everything that leaves.

Why

Agents read untrusted text: web pages, issues, READMEs, tool output. Any of it can steer them, and on your Mac they run as you, with your SSH keys, cloud creds, .env files and network. Permission prompts are the agent policing itself.

What zoo changes

The agent gets the worktree and nothing else. It can reach only what you've allowed: web hosts, and named services you grant per cage. Secrets stay on the host; keys sign without ever leaving the vault. Every request, connection and signature is logged and shown live.

What it does

Cages

One sandbox per worktree: a VM on Apple container, or a container on Docker/OrbStack/Podman. CPU, memory and process limits; every capability dropped; agents run unprivileged.

Keeper

squid on its own instance, the only thing a cage can reach. Default-deny allowlist by hostname, private addresses always refused, every new host approved by hand, every request logged.

Gate & services

Next to squid in the keeper. Forwards granted services (pg.zoo, redis.zoo, github.com:22) only to cages holding a grant.

Guarded worktree

Secrets like .env and *.pem read empty. .git/hooks, .git/config, other worktrees and submodules are read-only and pinned; repositories the agent plants in the worktree are flagged before your git runs them.

Keys stay home

Credentials stay on the host: cages get a placeholder the keeper swaps for the real token, only on the way to that credential's hosts, with a policy (read-only, push branches, repos). An SSH-agent proxy signs for allowed hosts without the key ever leaving the vault.

Dashboard

Loopback-only, token-guarded. Cages, isolation level, resources, grants, approvals and one feed of everything that left a cage.

Where it stands

Built and verified on Apple container 1.6.1, OrbStack, Docker Desktop and Linux CI
  • Backends: apple, docker, podman (contract suite on all three); escape suite in CI
  • Services: host port, sidecar, remote TCP, SSH agent; grants, expiring with --for
  • Credentials kept in the keeper; GitHub read-only, push branches, repos
  • zoo.yaml trust; git hook and config scan; git: rw|ro|none; several repos per cage
  • Previews, SSH door, package caches, custom images
  • zoo doctor --deep, interface check, gate anti-spoofing
